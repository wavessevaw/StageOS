# StageOS 1.0.2

Рабочая локальная версия с пустой базой. В поставке нет демонстрационных постановок, сотрудников, оборудования или календаря. Точные результаты проверок входят в архив соответствующего релиза. Сборка и настоящее окно проверены в Windows Server 2022 CI; ручная приёмка на Windows 10/11 ещё не выполнена.

## Первый запуск

1. В свойствах скачанного ZIP выберите «Разблокировать», если этот пункт есть; затем распакуйте архив полностью.
2. Запустите `StageOS/Windows-Portable/StageOS.exe`.
3. Введите название театра и нажмите «Создать рабочую базу».
4. В «Площадки» создайте технический паспорт. В «Сотрудники» добавьте людей и укажите цех/специализацию.
5. В «Добавить спектакль» заполните паспорт, выберите людей, добавьте имущество и требования. Сохраните постановку.
6. В «Назначить» выберите дату, постановку, состав и площадку. Проверьте предварительный план и подтвердите.

Встроенный Python и сервер запускаются приложением. Для окна нужны системный .NET Framework и Microsoft Edge WebView2 Runtime. Рабочая база и журнал ошибок: `%LOCALAPPDATA%\StageOS-Work`. Новый каталог выбран, чтобы прежняя демо-база не открылась автоматически. Старый `%LOCALAPPDATA%\StageOS` не удаляется. Существующую базу можно открыть через импорт в Настройках; импорт переносит её содержимое, включая любые старые демо-записи.

## Постановка

Разделы: основное, люди, техника, производство, адаптации. Роли хранят первый/второй состав и допущенный резерв; сотрудник выбирается из общего каталога. Можно добавить цех к команде. Оркестр, хор и балет находятся в разделе сотрудников и в группах постановки.

Техника включает комплекты, декорации, реквизит, костюмы, транспорт и поштучное имущество. Создание позиции в количестве 4 создаёт 4 ресурса с отдельными ID. Новое имущество сохраняется в каталоге даже при отмене редактирования постановки. Для декораций укажите размеры, массу, транспортные габариты и необходимость подвеса. Описательные паспорта звука/света/видео, работ, логистики и безопасности дополняют числовые ограничения. Длительность подготовки рассчитывается по этапам; переезд зависит от площадки.

Изменение паспорта не переписывает уже назначенные события. Карточка показывает сохранённые назначения и предупреждает об изменённом паспорте. Для применения нового наполнения используйте «Изменить» в событии и подтвердите новый предварительный план.

## Планирование

В предварительном плане можно изменить время/длительность этапа. Зависимости пересчитываются без записи в календарь. Прогон — опция, по умолчанию 11:00–14:00; монтаж должен действительно успеть к его началу. При изменении даты события ручные временные закрепления переносятся вместе с ним.

Для репетиции выберите нужные цеха и конкретных участников. Примечание сохраняется в событии. Замены, перенос и изменение длительности проходят повторную проверку. Отменённое, завершённое, идущее событие и событие с введёнными фактическими работами нельзя перепланировать с уничтожением истории.

Принудительное назначение требует причины от 12 символов. Конфликты остаются видны и записываются в историю. Невалидные данные и невозможные временные закрепления не сохраняются даже принудительно.

## Резервные копии

В Настройках экспортируйте SQLite-файл. Импорт проверяет целостность, структуру, паспорта и интервалы перед переключением базы. Не удаляйте рабочую папку при обновлении. Перед переходом со старой версии создайте резервную копию.

## Разработка и сборка

Исходники в репозитории wavessevaw/StageOS. Python 3.12, Node 22+, React/TypeScript, FastAPI, SQLAlchemy, Alembic, SQLite, OR-Tools. `requirements-lock.txt` и `frontend/package-lock.json` фиксируют зависимости.

`build_windows.ps1 -Mode Portable` собирает Win32 launcher и встроенный runtime. Tauri сохранён как альтернативный исходный host, его сборка не считается проверенной. Тестовые фикстуры разрешены только в режиме разработки с STAGEOS_ENABLE_DEMO=1 и не входят в packaged backend. Результат GitHub Actions оценивается по конкретному запуску, не по наличию workflow-файла.


## Постепенное заполнение постановки

Сохраните название и основные параметры даже без площадки или полного состава. Позже откройте «Постановки» → «Редактировать постановку» и дополните паспорт. Неверные и выведенные из эксплуатации ссылки не допускаются. При назначении недостающие исполнители выбранного состава показываются как конфликты.

В разделе «Люди» хор, балет, оркестр, грим, костюм и технические службы имеют первый и второй состав. Добавляйте сотрудников по одному. Составы независимы, пустой второй состав не копирует первый. Изменения паспорта не переписывают прошлые события.

## Язык и экспорт расписания

Верхняя панель → «Язык приложения» → Русский / English. Выбор сохраняется в базе и восстанавливается при следующем запуске. Названия постановок, имена и примечания остаются в исходном языке.

Календарь → «Экспорт расписания». Выберите период до 31 дня, PDF или PNG, включите необходимые вызовы, этапы и примечания. Учитываются текущие фильтры календаря. Несколько страниц PNG скачиваются ZIP-архивом; PDF содержит все страницы. Размер листа соответствует альбомному A3, шрифты встроены.

## Перенос рабочей базы

Настройки → «Скачать резервную копию» создаёт полный SQLite-файл с постановками, ресурсами, календарём, назначениями, историей и настройками. В другом экземпляре выберите «Открыть существующую базу» и загрузите этот файл. Успешный импорт сохраняется в отдельную управляемую копию и выбирается для следующих запусков. Исходная база не перезаписывается. Некорректный импорт не меняет действующую базу. Максимальный размер импортируемого файла: 64 МБ.

Копию храните отдельно от рабочей папки. Экспорт расписания PDF/PNG не заменяет резервную копию базы.

Версия 1.0.2 исправляет отображение импортированных объектов: источники, участие и постановочные титры показываются отдельными читаемыми разделами. Повторный импорт базы не требуется.
