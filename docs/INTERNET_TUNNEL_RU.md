# Интернет-доступ StageOS 1.0.9

ngrok выступает сервером-посредником: установленный на главном ПК агент устанавливает исходящее соединение, а пользователи StageOS подключаются к его HTTPS-адресу. База и аккаунты остаются на главном ПК. Код подключения и личный пароль требуются и через Интернет.

## Главный ПК

1. Запустите **StageOS Server.exe**, выберите театр и войдите администратором.
2. Откройте индикатор сервера → **«Доступ через Интернет»**.
3. Нажмите **«Установить ngrok»**. Приложение загрузит Windows x64 агент 3.39.11 с официального сайта и проверит SHA-256. Ключ на этом шаге не нужен. Если поставщик изменит архив, несовпадающая контрольная сумма остановит установку; потребуется обновление приложения.
4. Создайте аккаунт на https://dashboard.ngrok.com и скопируйте **Authtoken** из раздела Your Authtoken. Это ключ агента, не API key.
5. Вставьте его в поле **«Authtoken ngrok»**. По желанию включите сохранение для текущего пользователя Windows. Сохранённый файл шифруется Windows DPAPI; открытый ключ не записывается в настройки, журнал или командную строку. При запуске он передаётся только в окружение дочернего процесса ngrok. Администратор Windows с доступом к процессам сохраняет возможность прочитать память.
6. Нажмите **«Запустить интернет-туннель»**. Дождитесь статуса **«Интернет-туннель подключён»** и **«Проверенного внешнего адреса»**.
7. Передайте пользователям внешний адрес и код подключения StageOS. Добавьте их личные аккаунты через «Пользователи и роли». Authtoken им не нужен.

Приложение проверяет идентификатор именно этого запуска StageOS Server и ответ с кодом подключения через внешний адрес. Сам факт запуска ngrok не считается успешным подключением.

## Компьютеры пользователей

Запустите **StageOS.exe** той же версии → «Настроить подключение» → «Подключиться к серверу». Введите проверенный HTTPS-адрес и код, нажмите «Проверить и подключиться». Затем выберите театр и войдите своим личным логином и паролем. Данные не копируются в отдельную редактируемую базу клиента.

Обычный браузер вместо установленного клиента этим релизом не поддерживается. Клиент обходит служебную страницу ngrok с помощью документированного заголовка `ngrok-skip-browser-warning`.

## Остановка и сбои

- «Остановить туннель» завершает только агент, локальная сеть продолжает работать.
- Остановка сервера, переход к локальной базе, смена порта и закрытие StageOS Server останавливают туннель. После перезапуска приложения туннель запускается вручную.
- «Удалить сохранённый ключ» останавливает туннель и удаляет сохранённый ключ с этого ПК; отзыв ключа у поставщика выполняется в аккаунте ngrok.
- Неверный ключ, закрытый агент и отсутствие внешнего ответа дают ошибку или статус потери связи. При потере проверки внешний адрес не показывается как проверенный. Агент сам пытается восстановить сетевую сессию; при завершении процесса запустите туннель повторно.
- Главный ПК должен быть включён, не спать, иметь доступ к Интернету, а приложение должно оставаться открытым. Туннель не превращает приложение в службу Windows.

## Ограничения и проверка

Доступность, разрешённые адреса, одновременные соединения и квоты зависят от ngrok и аккаунта пользователя. Регулярное обновление клиентов и проверки связи расходуют HTTP-запросы: для длительной командной работы оцените лимиты аккаунта. Свой сервер-посредник, VPN и произвольные домены в этой реализации не настраиваются.

HTTPS завершается на стороне ngrok, который передаёт запросы к локальному HTTP-серверу. Это внешний поставщик с доступом к проходящему трафику, а не сквозное шифрование до StageOS. Локальный инспектор запросов ngrok выключен. Приложение не открывает HTTP-порт напрямую в Интернет и не требует проброса порта роутера.

Автоматические тесты проверяют управление, жизненный цикл, права, идентификацию сервера, обработку потери связи и интерфейс RU/EN. Проверка реального внешнего подключения с аккаунтом пользователя не выполнена: после настройки проверьте вход и создание временной записи со второго ПК вне локальной сети. Если связь оборвалась после сохранения, сначала проверьте календарь — сервер мог успеть принять запрос.

Документация поставщика: https://ngrok.com/docs/gateway/agent/config/v3 и https://ngrok.com/docs/pricing-limits/free-plan-limits.
