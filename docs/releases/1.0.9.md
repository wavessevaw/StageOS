# StageOS 1.0.9 — интернет-туннель и многодневные планы

## Интернет-подключение

В StageOS Server добавлена панель «Доступ через Интернет»: установка проверенного ngrok 3.39.11, запуск и остановка туннеля, статус, журнал и проверенный HTTPS-адрес. ngrok выступает посредником; база остаётся на вашем ПК. Требуется аккаунт ngrok и Authtoken на сервере. Пользователи подключаются из StageOS.exe по адресу и коду, затем входят личным аккаунтом.

Адрес считается проверенным только после ответа именно этого запуска сервера через внешний адрес и успешной проверки кода. Управление закрыто для удалённых клиентов и доступно администратору на серверном ПК. При остановке сервера, смене режима/порта и закрытии приложения агент завершается. Автоматического запуска туннеля при следующем открытии приложения нет.

Сохранение ключа необязательно и использует Windows DPAPI текущего пользователя. Ключ не записывается в открытом виде в настройки, журнал или командную строку. Локальный инспектор ngrok отключён. Установка скачивает агент отдельно с официального сайта с проверкой SHA-256; агент не включён в архив приложения.

ngrok — внешний поставщик, завершающий HTTPS и передающий трафик к ПК сервера. Это не собственная инфраструктура StageOS. Доступность и квоты зависят от аккаунта, включая расход запросов регулярным обновлением данных. Произвольные домены и обычный браузер вместо клиента не поддерживаются. Реальное подключение через ngrok с аккаунтом пользователя не проверено. Подробная инструкция включена в архив: `docs/INTERNET_TUNNEL_RU.md`.

## Планирование и сотрудники

- Погрузка, перевозки, разгрузка, монтаж и другие этапы могут находиться в разные дни относительно спектакля. Диапазон крайних дат — до 31 дня; отдельный редактируемый технический этап — до 7 дней.
- Исправлена сетка выбора сотрудников и служб на репетицию.
- У сотрудника можно явно задать несколько квалификаций. Назначение на обязанности фильтруется по допускам.
- Добавлено управление справочником квалификаций театра: создание и удаление неиспользуемых квалификаций. Используемые защищены с указанием зависимостей.
- Помощник отвечает по выбранной базе театра; исправлены сопоставления оборудования и проверки RU/EN.

Между первым и последним использованием бронирования остаются непрерывными: ночные и межэтапные перерывы автоматически ресурсы не освобождают. Посменное назначение по дням не добавлено.

## Обновление и проверки

Сделайте резервную копию, закройте клиент и сервер, распакуйте новую версию отдельно. Обновите сервер и клиентов одновременно. Рабочие данные сохраняются в `%LOCALAPPDATA%\StageOS-Work`. Не переносите файл общей базы в GitHub или синхронизируемую папку.

Публикация выполняется только после успешных backend/UI и Windows Portable проверок GitHub Actions. Точные результаты и ограничения приложены к архиву. Windows 10/11 на пользовательском ПК и реальное подключение к ngrok требуют отдельной проверки.

## English

StageOS Server now manages ngrok Internet access: verified agent download, optional Windows DPAPI token storage, start/stop, status and a public HTTPS address verified against this running server instance and connection code. Clients still need the connection code and personal login. Remote clients cannot manage the tunnel. Stopping the server or closing the app stops its agent; restart it manually after reopening. ngrok is an external relay provider with its own availability and quotas; real account-backed Internet access has not been tested.

This release also includes multi-day production stages, fixed rehearsal employee layout, explicit multiple employee qualifications, a theatre qualification catalogue with protected deletion, and database-grounded assistant fixes. Resource bookings remain continuous between first and last use. Back up and update server and clients together.
