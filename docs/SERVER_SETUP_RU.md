# StageOS Server 1.0.5 — настройка общей базы

Ваш компьютер хранит базу театра. Остальные компьютеры подключаются к нему через StageOS, входят под своими логинами и работают с одними актуальными данными. Файл SQLite не нужно размещать в общей папке, GitHub или облачной синхронизации.

## Главный компьютер

1. Сделайте экспорт базы в настройках и закройте прежнюю версию.
2. Полностью распакуйте архив 1.0.5. Данные в `%LOCALAPPDATA%\StageOS-Work` сохраняются.
3. Подключите ПК к доверенной сети театра. В Windows задайте этой сети профиль **«Частная»**. Желательно использовать кабель.
4. Запустите **StageOS Server.exe** из `Windows-Portable`. Отдельно StageOS.exe на этом же компьютере не запускайте.
5. Выберите существующий театр и войдите администратором. Для нового театра сначала создайте пространство и администратора.
6. Откройте меню личного аккаунта справа вверху → **«Подключение к серверу»**.
7. Режим **«Сервер на этом компьютере»** уже включён при запуске StageOS Server.exe. При запуске обычного StageOS.exe выберите этот режим и нажмите «Запустить сервер». Порт по умолчанию **8765**.
8. Убедитесь, что видны «Сервер работает», адреса и код подключения.
9. Нажмите **«Разрешить подключения в Windows»** и подтвердите системный запрос. Правило действует только для частной сети, локальной подсети и выбранного TCP-порта. Если правила контролирует организация, обратитесь к её системному администратору.
10. Передайте сотрудникам сетевой адрес, например `http://192.168.1.10:8765`, и код. **127.0.0.1 работает только на самом сервере.**
11. Нажмите «Продолжить» и при необходимости снова войдите.

Оставьте приложение открытым, компьютер включённым. Отключите автоматический сон на время работы. На серверном ПК можно одновременно работать с расписанием. Режим и порт запоминаются, но после перезапуска сервера пользователи должны снова войти.

## Пользователи

Администратор открывает **«Пользователи и роли»** в меню личного аккаунта и добавляет людей выбранного театра.

| Роль | Доступ |
|---|---|
| Администратор | Все операции, пользователи, импорт/экспорт базы, согласования, принудительное назначение |
| Планировщик | Редактирование расписания и паспортов без административных операций |
| Наблюдатель | Просмотр |

Сотрудник в справочнике и пользователь входа — разные сущности. Добавление артиста или техника не создаёт логин автоматически. Код подключения выбирает сервер и не заменяет личный пароль. Новые пространства и первого администратора создают на серверном ПК.

## Остальные компьютеры

1. Распакуйте эту же версию **1.0.5** и запустите **StageOS.exe**.
2. На экране выбора театра нажмите **«Настроить подключение»**.
3. Выберите **«Подключиться к серверу»**.
4. Введите адрес главного ПК и код.
5. Нажмите **«Проверить и подключиться»**. При неверном коде или недоступном сервере настройки не применятся.
6. Выберите театр сервера и введите личный логин и пароль.

Подключение сохраняется после повторного запуска. Данные остаются на сервере; отдельная редактируемая копия его базы на клиенте не создаётся. Локальная база, которая была у клиента раньше, сохраняется отдельно и автоматически не сливается с серверной.

## Проверка настройки

Создайте временную запись сотрудника на сервере. На клиенте откройте «Сотрудники»: запись должна появиться примерно за **5 секунд**. Затем создайте запись с клиента и проверьте её на сервере. Проверьте календарь и назначение события. Выйдите из аккаунта на одном ПК — другие продолжают работу. Удалите временные записи.

Попросите администратора сети закрепить IP главного ПК в роутере. Если адрес изменится, укажите новый адрес в настройках подключения клиентов.

## Выход, переключение и резервная копия

- «Выйти из аккаунта» завершает личный сеанс, сервер продолжает работу.
- «Переключить театр» открывает пространства того же сервера.
- «Подключение к серверу» позволяет выбрать другой сервер или вернуться к локальной базе.
- Остановка сервера или изменение порта на главном ПК требуют администратора. Закрытие приложения тоже останавливает сервер.
- Экспортируйте базу каждого театра через интерфейс. Для полной копии всех театров и аккаунтов **закройте сервер** и скопируйте каталог `%LOCALAPPDATA%\StageOS-Work`. Если ранее импортированная база хранится в другом месте, включите и её файл в копию. Не копируйте только основной SQLite-файл во время работы: журнал WAL может содержать последние изменения.

## Если не подключается

| Проблема | Что проверить |
|---|---|
| Сервер недоступен | ПК включён, не спит, приложение открыто; адрес и порт верны; устройства в одной сети |
| Неверный код | Скопируйте текущий код из окна сервера без лишних пробелов |
| На сервере работает, на другом нет | Используется сетевой адрес, а не 127.0.0.1; сеть частная; правило брандмауэра разрешено; Wi-Fi не изолирует клиентов |
| Порт занят | Закройте другой экземпляр или выберите свободный порт и обновите адрес на клиентах |
| Неверный логин / пароль | Пользователь создан в выбранном театре и не отключён |
| Версия плана устарела | Другой пользователь изменил данные. Откройте актуальное событие и повторите проверку |
| Сервер перезапущен | Войдите заново |

При потере связи сохранение возвращает ошибку. Если связь оборвалась сразу после отправки, после восстановления проверьте календарь: сервер мог успеть выполнить запрос. Журнал запуска: `%LOCALAPPDATA%\StageOS-Work\startup-error.log`.

## Границы версии

Режим рассчитан на доверенную локальную сеть и использует HTTP. Для доступа извне нужен VPN или отдельно настроенный HTTPS reverse proxy. Не открывайте HTTP-порт напрямую в интернет. Клиент принимает HTTPS-адрес, но настройка внешнего HTTPS и VPN не входит в автоматическую установку. Обычный браузер без установленного клиента пока не поддерживается.

Сервер — обычное приложение, не служба Windows. Автозапуск при входе в Windows отдельно не настроен. Для каждого театра используется одна SQLite-база на сервере с последовательной обработкой записи. PostgreSQL пока не внедрён. Приложение не шифрует диск; Windows-владелец ПК сохраняет доступ к локальным файлам.
