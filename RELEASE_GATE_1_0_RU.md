# Подготовка StageOS 1.0.0: аудит с недоверием к данным

Дата: 4 октября 2026. Исходная версия: 1.0.0-rc.1, коммит 6e300bb5d241c401ea5da3af891ff8e6ed3f14f0.
Текущая проверяемая версия: 1.0.0-rc.2. Стабильный тег 1.0.0 пока не создан.

## Найдено и исправлено

- Общий API ресурсов обходил проверку технического паспорта площадки. Теперь оба пути используют одну валидацию; изменение количества подвесов обновляет отдельные ресурсы.
- Некорректные параметры переезда, транспортных габаритов и логических флагов могли сохраняться и ломать расчёт. Они отклоняются до записи.
- Логические значения принимались за идентификаторы; неизвестные позиции замен игнорировались. Теперь команда отклоняется.
- Календарный диапазон терял подготовку перед началом спектакля и включал соприкасающиеся границы. Диапазоны учитывают задачи и используют полуоткрытые интервалы.
- Одновременные фильтры человека и оборудования учитывали только человека. Теперь это пересечение фильтров.
- Уже отменённое событие можно было отменять повторно и дописывать ему фактические работы. Отмена стала терминальным состоянием.
- Сохранённые события не обновляли конфликты после изменения часов работы площадки, квалификаций людей и нагрузки назначенных штанкетов. Проверяются именно сохранённые назначения; автоматическая подмена ресурсов не выполняется.
- Импорт проверял не все части сохранённого плана. Теперь проверяются структура, соответствие команды событию, задачи, бронирования, ссылки на сотрудников, фактические интервалы и настройки.
- Выбор импортированной базы теперь записывается атомарно до смены активной базы. Повреждённый импорт оставляет исходную базу активной.
- Согласование предложения использует SQLite BEGIN IMMEDIATE, как прямое назначение.
- Производственный календарь не обновлялся при изменении фильтров; недоступности игнорировали подразделение. Добавлен актуальный пересчёт представления.
- Проверка пройдена также для восстановления базы с действующими конфликтами: потеря квалификации не делает корректную резервную копию неимпортируемой. Исторические ссылки сохранённых событий защищены от удаления.
- Неполные настройки ИИ вызывали необработанную ошибку. Теперь выдаётся ошибка проверки, ядро остаётся доступным.
- Согласованная иконка включена в интерфейс, favicon, ICO окна и ресурсы Windows EXE. Новый UI-тест обнаружил и помог исправить неверную выдачу SVG сервером.
- Удалено дублирование чтения предпочтения базы из Windows-оболочки: используется общий механизм ядра.

## Фактические локальные проверки

- До изменений: 74 backend-теста прошли.
- Первая серия из 19 независимых проверок: 15 не прошли, 4 прошли. Это варианты воспроизведения ошибок, а не число уникальных дефектов.
- После основных изменений: 94 backend-теста прошли за 111,50 с.
- Полный повторный прогон: 97 backend-тестов прошли за 111,14 с.
- Дополнительные проверки восстановления конфликтного состояния и защиты исторических ссылок выполняются в окончательном наборе из 100 тестов.
- Основной интерфейс: 15 сценариев прошли за 45,7 с, включая настоящий drag/resize с предварительным пересчётом.
- Интерфейс пустой базы: 2 сценария прошли за 7,3 с; создание ресурсов и постановки, назначение, перезагрузка, фильтры производства и иконка.
- TypeScript и production build: прошли. Vite сообщает о крупном JS-файле; это не ошибка сборки.
- Статический анализ критических ошибок Python и компиляция модулей: прошли.
- Windows лаунчер с ICO и сведениями версии кросс-компилирован в PE32+ x64.

Повторная полная проверка и Windows CI выполняются на коммите PR. Источник фактического результата — GitHub Actions, не этот предварительный документ.

## Ошибка, выявленная только на Windows

Первый Windows-прогон остановился на экспорте базы: соединения SQLite оставались открытыми после выхода из транзакционного контекстного менеджера, и удаление временного файла давало WinError 32. Исправлено явное закрытие всех соединений импорта/экспорта. Добавлен тест, проверяющий закрытие, даже на Linux.

## Что проверяется в Windows CI

Сборка Portable, backend-тесты на Windows, встроенный Python, SQLite/CP-SAT, импорт CLR/WinForms, запуск настоящего окна WebView2, загрузка React, передача токена, иконка окна и завершение сервера после закрытия. Диагностические квитанции прикладываются отдельным артефактом. Для окна используется Windows Server 2022 runner; это не заменяет проверку на пользовательских Windows 10 и 11.

## Проверка редактора постановки

Есть основные сведения и длительность, две версии состава и резерв, роли и сцены, ответственные и команды цехов, хор/балет/оркестр, комплекты и отдельные единицы имущества, декорации/реквизит/костюмы/транспорт, количественные технические требования, зависимости подготовки, адаптации площадок и описательные технические паспорта. Ссылки и числовые поля проверяются ядром.

Ограничения: два состава; сигнальные маршруты и меры безопасности являются описанием, а не отдельным вычислительным графом. Время и бригада отдельной декорации не изменяют автоматически длительность общего монтажа. Запасы резервируются по конкретным единицам, а не по обезличенному количеству. Система не заменяет инженерный расчёт несущих конструкций и согласование реальной площадки. Изменение паспорта применяется к событию только через новый предварительный план.

## Условия готовности стабильной версии

Все проверки должны пройти на окончательном коммите. Поставка — пустая база без демо-данных. Дополнительно требуется подтвердить первый запуск, закрытие, повторный запуск и импорт/экспорт на Windows 10/11, включая путь с кириллицей и пробелами и архив, скачанный из браузера. Сейчас подписанного установщика нет; WebView2 остаётся системной зависимостью. Проверка реальных локальных моделей и PostgreSQL не выполнена. Существующий публичный RC1 не переименовывается и не перезаписывается.
